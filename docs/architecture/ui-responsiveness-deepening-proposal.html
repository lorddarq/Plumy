Candidate 01

Deepen Workspace state and shell projection

Strong in-process
Files
src/app/store/workspaceStore.tsx · src/app/store/uiLayoutStore.tsx · src/app/hooks/useAppShell.ts · src/app/App.tsx · src/app/components/views/AppMainViews.tsx

After · selected state, stable projection

Small subscription interface

Persistence
Projection

Problem

Workspace and layout modules expose nearly their full implementation, so unrelated changes invalidate one coarse seam and force defensive memoization downstream.

Solution

Deepen the Workspace subscription and projection module so selection, stable identity, persistence, and view projections stay behind one smaller interface.

Benefits

  • ✓ locality: state ownership concentrates
  • ✓ leverage: one projection seam
  • ✓ Poll churn stops early
  • ✓ Tests observe render isolation

Problem

Three modules independently poll, subscribe, sort, select, and derive pending input from the same ACP session stream, creating redundant work and inconsistent snapshots.

Solution

Deepen the supervision registry so observation, deduplication, task-scoped selection, activity, and attention stay behind one renderer seam.

Benefits

  • ✓ One session observation path
  • ✓ locality: lifecycle interpretation
  • ✓ Fewer IPC round trips
  • ✓ Interface becomes test surface

Problem

Viewport observation, infinite dates, geometry, task indexing, track planning, drag behavior, and rendering are fused; the unused 203-line virtualization module duplicates intent without leverage.

Solution

Delete the unused module and deepen one Timeline viewport module that owns visible ranges, indexed rows, geometry, and scroll compensation.

Benefits

  • ✓ Remove O(rows × tasks)
  • ✓ Delete duplicate window intent
  • ✓ locality: viewport behavior
  • ✓ DOM adapter is replaceable

Problem

The runner is already deep, but reusable provider sessions and task execution turns remain interleaved across start, resume, continue, event, and task-attempt synchronization flows.

Solution

Keep the runner’s external seam and deepen its internal session and turn modules; absorb stable in-process plumbing while preserving the real provider adapter.

Benefits

  • ✓ Preserve existing external seam
  • ✓ locality: lifecycle transitions
  • ✓ Smaller test harness
  • ✓ Loop fixes stay internal

Top recommendation

Deepen Workspace state and shell projection

It has the highest leverage: one smaller subscription seam prevents unrelated polling and layout state from reaching every planning view, replacing downstream render shields with locality at the source.
